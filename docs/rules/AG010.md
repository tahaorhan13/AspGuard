# AG010: Dynamically built SQL passed to a raw SQL method

| | |
|---|---|
| Category | Security |
| Default severity | Warning |
| Code fix | Yes, for `string.Format` with a constant format string (see below) |

## Cause

The `sql` argument of `FromSqlRaw`, `ExecuteSqlRaw`, `ExecuteSqlRawAsync` or `SqlQueryRaw` is a **string that was built at
run time**, so values end up *inside* the SQL text instead of being sent as parameters: a SQL injection risk.

Reported:

- `string.Format(...)`, `string.Concat(...)`, `string.Join(...)`, `string.Replace/Insert(...)` with non-constant arguments,
  directly as the argument;
- `StringBuilder.ToString()`;
- a **local variable** whose value was built with interpolation, concatenation, `+=`, `string.Format` or `StringBuilder`
  anywhere in the same method.

**Not reported here (to avoid duplicate warnings):** an interpolated string or a `+` concatenation written directly in the
argument. EF Core's own analyzer reports those as
[EF1002](https://learn.microsoft.com/ef/core/querying/sql-queries#passing-parameters). Constants, `const` strings and
strings that merely arrive as a method parameter are never reported.

## Example

```csharp
var sql = $"SELECT * FROM Orders WHERE Name = '{name}'";
var orders = db.Orders.FromSqlRaw(sql);                                         // AG010

var more = db.Orders.FromSqlRaw(string.Format("SELECT * FROM Orders WHERE Id = {0}", id));   // AG010
```

## How to fix

Let EF Core parameterize the values with the interpolated overloads, or pass explicit parameters:

```csharp
var orders = db.Orders.FromSql($"SELECT * FROM Orders WHERE Name = {name}");
var more   = db.Orders.FromSqlRaw("SELECT * FROM Orders WHERE Id = {0}", id);
```

(`{name}` in `FromSql` becomes a parameter; do not put quotes around it.)

### Code fix

`FromSqlRaw(string.Format("... {0} ...", x))` becomes `FromSql($"... {x} ...")` (likewise `ExecuteSql`, `ExecuteSqlAsync`,
`SqlQuery`). It is offered only when it is safe:

- the format string is a constant and uses plain `{n}` placeholders (no `{0:N2}`, `{0,5}`, `{{`);
- no placeholder sits inside a quoted SQL literal such as `'{0}'` (the interpolated version would produce a quoted
  parameter, which changes the meaning: remove the quotes by hand);
- the call has no extra parameter arguments.

Note that the fix changes behavior on purpose: values are now sent as parameters instead of being pasted into the SQL.

## When to suppress

Only when the dynamic part is not user-controlled (for example a table name chosen from a fixed allow-list). Prefer
`#pragma warning disable AG010` with a comment explaining why it is safe. This rule is **not** affected by
`aspguard.scope = attributed_only`.
