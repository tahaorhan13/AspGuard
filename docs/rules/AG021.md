# AG021: Blocking on an EF Core async call

| | |
|---|---|
| Category | Performance |
| Default severity | Warning |
| Code fix | No |

## Cause

`.Result`, `.Wait()` or `.GetAwaiter().GetResult()` is applied **directly** to an EF Core async call
(`ToListAsync`, `FirstOrDefaultAsync`, `FindAsync`, `SaveChangesAsync`, `ExecuteSqlRawAsync`, ...). The calling thread
blocks while the database works, which wastes a thread-pool thread and can deadlock in code that has a synchronization
context.

Not reported: tasks that were stored in a variable first, and `.Result`/`.Wait()` on tasks that are not EF Core calls.

## Example

```csharp
var orders = db.Orders.ToListAsync().Result;            // AG021
db.SaveChangesAsync().GetAwaiter().GetResult();          // AG021
```

## How to fix

Make the calling method `async` and `await` the call, or use the synchronous EF Core API (`ToList`, `SaveChanges`) if the
code is genuinely synchronous.

## When to suppress

In rare entry points that cannot be async (for example `Main` of a legacy console app). Prefer the synchronous
`ToList()`/`SaveChanges()` there instead of blocking on the async version.
