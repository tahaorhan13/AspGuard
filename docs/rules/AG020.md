# AG020: Filtering in memory after loading a whole table

| | |
|---|---|
| Category | Performance |
| Default severity | Warning |
| Code fix | No |

## Cause

`ToList()`, `ToArray()` or `AsEnumerable()` (or `await ...ToListAsync()` / `ToArrayAsync()`) on an EF Core query is
**directly followed** by LINQ-to-Objects `Where` or `Select`. All rows are transferred to the application and then
filtered or projected there, instead of in the database.

Not reported: queries bounded with `Take`/`TakeLast` before materializing, in-memory lists, and results that were
stored in a variable first (the rule only looks at the direct chain).

## Example

```csharp
var adults = db.People.ToList().Where(p => p.Age >= 18).ToList();   // AG020
var names  = db.People.AsEnumerable().Select(p => p.Name).ToList();  // AG020
```

## How to fix

Filter and project before materializing:

```csharp
var adults = db.People.Where(p => p.Age >= 18).ToList();
var names  = db.People.Select(p => p.Name).ToList();
```

## When to suppress

If the predicate genuinely cannot be translated to SQL (it calls your own method), narrow the query as much as you can
in the database first and then suppress the warning on the in-memory part.
